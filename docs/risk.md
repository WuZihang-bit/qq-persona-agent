# 风控与封号

自动化运营 QQ 号有真实的封号风险。这一页没有废话，都是实测经验。

## 风控长什么样

- 账号被踢下线（NapCat 日志：`账号状态变更为离线`），需要重新扫码
- 严重的会触发验证码/冻结，新号最容易中招

## 实测触发因素（按风险排序）

1. **新号 + 当天高频登录切换**：刚注册的号当天反复登录/掉线/再登录，几乎必被盯上
2. **消息频率**：短时间大量发消息（尤其是多群同时活跃）
3. **多设备打架**：手机和 PC/NapCat 频繁互顶
4. **消息内容同质化**：连续多条风格雷同的消息（本项目的随机延迟/长度变化正是为此）

## 降险清单

- [ ] 固定一台设备挂 NapCat，手机上少动小号
- [ ] 控制每日消息总量（group-lurker 的 DAILY_CAP）
- [ ] 保留静默时段（23:30~8:00），像人一样作息
- [ ] 新号前几天用最低档频率，逐步放开
- [ ] 手动用小号做点真人行为：刷空间、点赞、改签名
- [ ] 小号不绑支付、不存资产——炸号不心疼
- [ ] 云服务器部署选**国内**节点，海外 IP 对 QQ 风控更敏感

## 被踢之后

1. NapCat 快速登录重连（`node index.js -q <QQ号>`）；凭证失效则重新扫码
2. 一天被踢 ≥2 次 = 风控信号，降频或停几天
3. 永久冻结的号救不回来，换号重来

## 免责

自动化使用个人 QQ 号可能违反腾讯服务条款，后果（限制、冻结）由使用者自担。本项目不提供任何"绕过风控"的手段——那不属于技术问题，属于对抗问题，也不该做。
